# Сетевые схемы для проверки ИБ

Агент проверяет обезличенные листы. Человек (автор пакета) заполняет реальные адреса и имена
в отдельной копии для отправки. Агенту доступны коды, номера связей и id ячеек.
См. [правила работы с копиями и манифестом](references/copies.md).

## Вызов

Нужны Node.js 24+ и npm. Установщик помещает навык в `~/.agents/skills/sec-diagrams`.
При установке плагина навык остается внутри него, а `$SKILL_DIR` указывает на папку с `SKILL.md`.
В каждой команде подставляй вместо `$SKILL_DIR` абсолютный путь к каталогу этого SKILL.md
или задавай переменную в том же вызове оболочки. Пример проверки из рабочей папки:

```sh
node "$SKILL_DIR/tools/cli.ts" check ./sample
```

Для `pdf` и `pack` нужны draw.io Desktop и MuPDF.js. Установи движок вручную
командой `npm install --prefix ~/.sec-diagrams mupdf@1.28.6` (AGPL-3.0-or-later). Если программа установлена в другом месте,
задай в `SD_DRAWIO` путь к исполняемому файлу. Экспорт через сеть исключен.
Последняя строка `Дальше:` дает команду, `Человеку:` называет ручной шаг.
В `check --json` смотри `findings`, `warnings` и `notChecked` (причина и поле `file`, если есть путь).

## Только проверка

[агент] На просьбу "проверь" выполни `node "$SKILL_DIR/tools/cli.ts" check <папка>`.
Сообщи код, файл, страницу и id для замечаний. Перечисли пропущенные и ручные проверки.
На этом остановись, даже если CLI предлагает исправление или сборку.
Для пустой папки уточни путь к исходным листам.

## Ответ человеку

- Отвечай по-русски, если человек не попросил о другом языке.
- Команды, имена файлов, идентификаторы и диагностические коды копируй дословно, как их вывел CLI.
- Называй то, о чем пишешь, прямо: без своих сокращений, англицизмов, терминов и номеров. Шаги можно нумеровать.
- Из сокращений и английских слов используй только общеизвестные. Расшифруй специальные термины при первом упоминании.
- Для каждого замечания дай код из вывода CLI, файл, страницу и `id`, если они есть, и простыми словами, что не так.
- Для ручных проверок используй справочники из `references/`.

## Правка и подготовка

1. [агент] Если пакет уже отправляли, работай в обезличенной копии строго по списку изменений.
   Сверь снятые номера с `retired`. Новые связи добавляй по [инструкции к повторной отправке](references/resend.md).
2. [агент] Для нового пакета `init <папка>` создает четыре листа, `manifest.json` и `poc.yaml`.
   Существующие листы сохраняет. Пример манифеста рабочей копии:

   ```json
   {"service":"Служба ИБ","titlePrefix":"","final":false,"sheets":[{"file":"l1.drawio","level":"L1","topic":"Общая схема"}]}
   ```

3. [агент] Укажи в строках правил МЭ номера связей L3 через `link`. Укажи назначение каждого правила. Для сверки собери лист командой `rules <папка>/poc.yaml`.
4. [агент] Для точечной правки используй `text get <файл> <id>`, `text set <файл> <id> "<текст>"`
   или `style set <файл> <id> <ключ>=<значение>`. Перевод строки в аргументе текста записывай как
   `\n`, обратную косую как `\\`. Для нового пакета применяй `fix --safe <папка>` по подсказке.
5. [агент] Повтори `check`. При отсутствии самого листа правил выполни `rules`; для другого
   пропущенного листа сверь имя с манифестом. Если замечание осталось после двух правок,
   сообщи человеку код и id. При FAIL команда `final` откажет.
6. [агент] По запросу на подготовку создай копию командой `final <папка> <новая папка>`.
   Если после final потребовалась правка схемы, согласуй изменения с человеком, сохрани его
   правки и создай следующую копию под новым именем. Перенос реальных значений делает человек.

## Передача человеку

- [человек] Заполни копию в draw.io и ее `poc.yaml`. Отметь открытые значения в записи о проверке.
- [агент] После заполнения пересобери лист `rules <копия>/poc.yaml --force` и выполни `check`.
  Проверь печать командой `pdf <копия>`. Результаты лежат в соседней папке с суффиксом `-pdf`.
- [агент] Команда `pack <копия>` создает рядом папку с суффиксом `-обзор`.
  В ней лежат `Обзор__Служба__N.pdf` (N листов) и папка `схемы/` с исходниками сетевых листов.
  Имя сетевого исходника начинается с темы, например `Прием телеметрии__L3-1.drawio`.
  По запросу добавь `--with-rules` для листа правил (в исходники и PDF) и `--with-letter`
  для записки. Флаги можно сочетать. `pack` читает `записка.txt` только с `--with-letter`.
  Команда `letter <копия>` создает каркас записки и проверяет заполненный файл отдельно от сборки.
- [человек] Проверь PDF на A3 и пройди чек-лист рядом с отчетом PDF. Если приложил записку,
  сверь список вложений с файлами пакета. Для каждой связи без правила подтверди, что она не пересекает МЭ.
  Зафиксируй результат и место проверки либо основание неприменимости. Отправь пакет сам.

## Чек-лист агента

- [ ] Выполнен маршрут из запроса, замечания и пропуски перечислены.
- [ ] После согласованных правок пройден повторный check.
- [ ] При подготовке пакета человек получил результаты печати и ручной чек-лист.
- [ ] Состав пакета соответствует запросу. Флаги `--with-letter` и `--with-rules` указаны для запрошенных приложений.

## Статусы и коды выхода

| Код | Результат |
| --- | --- |
| 0 | Автопроверки прошли. WARN обозначает рекомендацию автора. |
| 1 | FAIL или записка требует заполнения (для `letter` и `pack --with-letter`). |
| 2 | NOT_CHECKED (проверка пропущена) или UNVERIFIED (недостаточно данных для вывода). |
| 64 | Ошибка вызова или отказ в доступе к значению. |
| 65 | Ошибка входных данных, SD-E01 или SD-E02. |
| 69 | Нет зависимостей CLI. Выполни напечатанную команду npm ci. |

После чтения листов `NOT_CHECKED SD-G01` напоминает проверить геометрию глазами.
Только эта строка код выхода не меняет. По XML нельзя подтвердить кегль готовой PDF.

## Проверка старой отправки

Для комплекта, выпущенного до появления manifest.json, выполни
`node "$SKILL_DIR/tools/cli.ts" check <папка-с-листами> --submitted --json`.
Укажи папку с исходниками. Начни с PDF, который получил проверяющий.

1. Убедись, что каждый знак `?` на схеме отмечает допущение по легенде. Вопрос читателю запиши в итог проверки.
2. Сравни нумерацию с прошлой версией. Проверь, что за каждым новым пропуском стоит снятая связь.
3. Найди объяснение для каждого открытого обязательного поля в итогах проверки или в приложенной записке.

Запиши итог для каждой ячейки с замечанием. Для пакета с манифестом или маркером копии используй `check`.
У каждого применимого [критерия содержания](references/content-review.md) укажи вердикт и место,
на котором он основан. Если материалов мало, запиши, чего не хватает для проверки.
